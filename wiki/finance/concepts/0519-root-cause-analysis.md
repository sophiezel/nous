## 五条根因

### 根因1: 监控体系没有纵深防御

**现象**: 看门狗崩溃 → 所有监控失明20小时

**本质**: 整个系统的"眼睛"只有一个进程。它没有备份，没有"看门狗的看门狗"，崩溃后无人知晓。

**类比**: 一个哨兵守城门。哨兵倒下，敌军长驱直入，城内无人察觉。

**沉淀**: 任何关键监控组件必须有一个"更笨但更可靠"的二次监控。当前 system_health cron 仍在运行但不检查 watchdog 是否 alive。

### 根因2: 配置即代码——但没按代码对待

**现象**: `.env` 中 `ALLOW_ALL_USERS=false` + 空白名单 → 35h 后才发现

**本质**: 配置文件是系统运行的一部分，但既没有版本控制（gitignore），也没有变更验证（改了立即生效无校验），也没有审计追踪（不知道谁在05-18 02:34改的）。

**类比**: 飞机驾驶舱的开关。扳错了发动机就停。但没有飞行记录仪，也没有副驾驶复核。

**沉淀**: 
- 关键配置变更必须可追溯（git追踪 `.env.schema` + 实际值落盘到审计日志）
- 变更后必须即时验证（weixin_heartbeat 已新增 `check_weixin_config()`）
- "配置错误"应该是独立的告警类型，不被重启/修复循环掩盖

### 根因3: 数据库迁移没有回滚方案

**现象**: `stock_daily_v2` 迁移提交了，视图切换了，但数据从未迁移 → 所有消费者读到空表

**本质**: commit `c846e85` 做了三件事——创表、改视图、从不填数据。这是一个"未完成的迁移"，在生产环境跑了数天无人发现。因为没有人在迁移后验证"消费者能否读到数据"。

**类比**: 修了一座新桥，把路牌全改指向新桥，但新桥只建了桥墩没铺路面。

**沉淀**:
- 数据库迁移必须分三步：创表→填数据→切视图（不能三步合一）
- 迁移完成后必须有端到端验证（不是 `SELECT COUNT(*)` 而是模拟消费者查询）
- 迁移必须有回滚脚本（本次回滚即：DROP VIEW + 重建指向旧表）

### 根因4: 健康检查全是"表面检查"

**现象**:
- 网关进程活着 ✅ → 但所有用户被拒绝 ❌
- stock_daily 有 2.2M 行 ✅ → 但视图指向空表，消费者读到 0 行 ❌
- weixin_heartbeat 检测 rate_limited → 但那是一天前的旧日志

**本质**: 每个检查都在问"组件是否存活"而不是"功能是否可用"。进程存活≠服务可用，数据存在≠可被消费，配置存在≠配置正确。

**类比**: 医生只测心跳不测血压。病人心跳正常，但血管已经堵了。

**沉淀**:
- 健康检查必须是端到端的：发一条测试消息→验证送达→才算微信通道健康
- 日志分析只看"本次启动后"的日志，不被历史错误误导（weixin_heartbeat 已修复）
- "进程存活"只是第一步，必须验证"功能可用"

### 根因5: 故障传播没有隔离

**现象**: WeChat 熔断 → 看门狗崩溃 → 全部监控失效

**本质**: 一个外部依赖故障（微信API限流）击穿了整个监控体系。看门狗的 `check_cron_jobs()` 因为一个 `None` 值崩溃，导致整个 watchdong 进程退出。

**类比**: 一个房间灯泡烧了，整栋楼跳闸。

**沉淀**:
- 每个检查模块独立 try/except，单个模块失败不能导致全局崩溃（watchdog 已修复）
- 外部依赖故障不应触发 DOWN 标记（watchdog 已修复：只有微信故障才标记 WEIXIN_DOWN）
- "降级运行"优于"全有或全无"——微信断了至少 macOS 通知还应该工作

## 架构原则沉淀

从本次事故提炼五条工程铁律，写入系统设计规范：

### 铁律1: 纵深防御

```
任何P0组件必须有独立的外部监控
  → 看门狗 → 必须有 system_health 检查看门狗是否alive
  → 网关 → 必须有 weixin_heartbeat 检查功能可用性
```

### 铁律2: 配置即代码

```
.env变更 → git追踪 + 即时验证 + 审计日志
  已实现: weixin_heartbeat.check_weixin_config()
  待实现: .env 变更时写审计日志 + git追踪 .env.schema
```

### 铁律3: 迁移三步走

```
数据库迁移 = 创表 → 填数据 → 切视图（不可跳步）
  + 端到端消费验证
  + 回滚脚本
```

### 铁律4: 端到端验证

```
健康 ≠ 进程存活
健康 = 功能可用（端到端验证）
  日志过滤: 只看本次启动后的日志
```

### 铁律5: 故障隔离

```
每个检查模块独立 try/except
外部依赖故障不触发全局 DOWN
降级运行 > 全有或全无
```

## 落地检查清单

每次系统变更后，对照以下清单自查：

- [ ] 如果看门狗崩了，有谁会知道？(system_health 检查看门狗 alive？)
- [ ] 如果 `.env` 被人改了，多久能发现？(即时验证 + git diff？)
- [ ] 如果有人在凌晨提交了一个"半成品"迁移，生产环境会怎样？(回滚脚本？)
- [ ] "看起来好了"是真的好了吗？(端到端验证？)
- [ ] 一个组件挂了会导致全局崩溃吗？(故障隔离？)
