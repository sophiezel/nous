## 二、数据库Schema（12张表）

### 核心数据表（4张）
| 表 | 行数 | 索引 | 用途 |
|----|------|------|------|
| stock_basic | 5,578 | PRIMARY KEY(symbol) | 股票基本信息 |
| stock_daily | 635,766 | symbol+date, date | 日线OHLCV |
| stock_fundamental | 2,135 | PRIMARY KEY(symbol) | 基本面快照(UPSERT) |
| screen_results | 37,671 | screen_date+score, symbol+date | 筛选结果(90天滚动) |

### 质量保障表（5张）
| 表 | 用途 | 触发方式 |
|----|------|---------|
| data_audit_log | 所有写操作审计 | INSERT/UPDATE触发器自动写入 |
| data_provenance | 数据血缘追溯 | INSERT触发器+回填 |
| stock_fundamental_snapshots | 基本面历史快照 | UPDATE触发器自动保存旧值 |
| slow_query_log | 慢查询监控 | application层monitored_query() |
| etl_metrics | ETL耗时指标 | ETLSession自动记录 |

### 扩展表（3张）
| 表 | 用途 |
|----|------|
| index_daily | A股指数日线 |
| index_global_daily | 全球指数+汇率 |
| futures_daily | 商品期货 |

### 10个索引
```
stock_daily: idx_daily_symbol, idx_daily_date, idx_daily_sym_date
screen_results: idx_screen_date, idx_screen_date_score, idx_screen_sym_date
stock_fundamental_snapshots: idx_fund_snap_symbol, idx_fund_snap_date
data_audit_log: idx_audit_ts, idx_audit_table
data_provenance: idx_prov_symbol, idx_prov_source
slow_query_log: idx_slow_ts, idx_slow_hash
etl_metrics: idx_etl_task, idx_etl_session
```

### 8个触发器
```
trg_daily_quality_insert    — close>0, high>=low, volume>=0 硬约束
trg_daily_audit_insert      — 每次INSERT记录审计
trg_daily_audit_update      — 每次UPDATE记录审计
trg_fund_audit_insert       — 基本面INSERT审计
trg_fund_audit_update       — 基本面UPDATE审计
trg_fund_snapshot_on_update — UPDATE前保存旧值到快照表
trg_screen_audit_insert     — 筛选结果INSERT审计
trg_daily_provenance        — 日线INSERT记录血缘
trg_audit_cleanup           — 审计日志>100K行自动清理
```

## 三、P0策略改善（3项）

### P0-1: Soul Engine管线贯通
- **文件**: `~/.hermes/scripts/theme_recommend.py`
- **改动**: 新增 `get_soul_diagnosis()` 函数, 荐股输出前对每只候选股执行soul_engine.diagnose()
- **效果**: 每条荐股附带L1通道/L2品质/L3赔率/L4趋势/L7共振诊断
- **输出示例**: `🧠 消费垄断 | ✅ | 低赔率 | 弱多头 | 🔴`

### P0-2: 基本面覆盖率兜底
- **文件**: `src/indicators/value.py`
- **改动**: `_market_fallback()` A股fallback从固定PE=50/PB=5 → 实时A股PE中位数(56.8)/PB中位数(3.22)
- **效果**: 无基本面标的的评分更接近市场真实水位

### P0-3: 短线交易引擎
- **文件**: `src/short_term_engine.py` (814行)
- **内容**: 5位游资方法论编码为可执行规则
  - 徐翔涨停板追涨: 昨日涨停+高开>3%+封单量>0.5% → 30%仓位
  - 赵老哥二板定龙头: 首板放量+二板缩量 → 25%仓位
  - 炒股养家情绪周期: 连板高度+涨停溢价 → hot/warm/cool/cold门控
  - 作手新一逻辑驱动: 涨幅>5%+量比>2+站上MA20 → 20%仓位
  - 方新侠拐点博弈: 连跌3天+RSI<30+放量阳线 → 15%仓位
- **CLI**: `python -m src.short_term_engine scan|check <symbol>`

## 四、Phase 1 四维加固

### 稳定层: 数据源健康评分
- **文件**: `src/data_quality/__init__.py` (HealthTracker)
- **机制**: 滑动窗口(100次)成功率×延迟衰减 → 0-100分
- **熔断器**: push2连续3次失败→OPEN(5分钟)→HALF_OPEN→CLOSED
- **注入**: `src/fetchers/a_share.py` fetch_daily() 每次调用自动记录成功/失败+延迟
- **持久化**: `~/.hermes/cache/source_health.json`

### 及时层: Gap检测+自动回补
- **文件**: `src/data_quality/gap_detector.py`
- **SLA**: stock_daily ≤1天滞后, stock_fundamental ≤2天, screen_results ≤1天
- **检测**: 当日入库量 < 昨日80% → 触发告警
- **回补**: 自动调用 `stock-screener update -m a` 补缺
- **cron**: gap-detector (16:50, 交易日)

### 准确层: 入库验证
- **文件**: `src/data_quality/validators.py`
- **日线**: close>0, high>=low, volume>=0, 涨跌幅检查, 量价背离
- **基本面**: PE 1-5000, PB 0-50, ROE -100~100
- **注入**: `src/storage.py` upsert_daily()/upsert_fundamentals() 写入前验证
- **日志**: `~/.hermes/logs/anomalies.jsonl`

### 可用层: 健康仪表板
- **文件**: `src/data_quality/health_dashboard.py`
- **输出**: `~/wiki/finance/raw/data_health.json` + 摘要报告
- **内容**: DB统计+新鲜度+源健康分+最近异常
- **cron**: health-dashboard (07:55, 交易日)
